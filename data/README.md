# Data layout

Three tiers, by where the bytes came from. Nothing here mixes: check the directory
before you trust a file.

| Directory | Origin | Modify? | In git? |
|---|---|---|---|
| `raw/` | Provided by Kaggle | **Never** | Yes — the five CSVs |
| `external/` | Third-party, vendored from Kaggle datasets | **Never** | Yes, with `PROVENANCE.md` |
| `processed/` | Generated by our own scripts | Regenerate, don't edit | **No** — gitignored |

## `raw/`

The five competition CSVs. DICOM images are **not** versioned — they are tens of GB
and must be downloaded separately. See [`../docs/data.md`](../docs/data.md) for what
these files actually contain.

## `external/`

Public label tables and other third-party inputs, one directory per Kaggle dataset,
named `<owner>-<slug>`. Each carries a `PROVENANCE.md` with the source URL, author,
licence, download date, checksums, and its measured quality.

Committed rather than downloaded on demand: public Kaggle datasets are revised in
place, and pinning the exact bytes we measured against keeps results reproducible.
See [`../docs/labels.md`](../docs/labels.md) for the comparison between them.

## `processed/`

Derived artefacts. **Always safe to delete** — everything here is regenerated by a
script, and gitignored precisely so that a stale derived file cannot outlive the
code that made it.

```bash
python -m scripts.blend_labels --write default --out data/processed/report_labels_blend.csv
```
